## Confirmed statement

- **Outcome:** SRS / ระบบจองชุดเฟรชชี่ (โครง eCommerce) ชุดเดียว ครอบคลุมฝั่งนักศึกษา + ฝั่งเจ้าหน้าที่ ใช้เป็นต้นทาง implement ได้
- **User:** นักศึกษาจอง/จ่าย/ติดตาม; เจ้าหน้าที่ตรวจสลิป จัดการออเดอร์ จัดการสินค้าเต็มรูปแบบ และสร้างรอบเปิดจองที่ผูกสินค้า
- **Why now:** มีรายการใน `docs/features.md` แล้ว แต่ยังไม่ตัดขอบเขต v1 / Phase 2 และ workflow สำคัญให้ลงมือทำได้
- **Success:** อ่านข้อกำหนดแล้วรู้ว่า v1 ต้องทำอะไร จบเมื่อไหร่ถือว่าผ่าน และอะไรเลื่อนได้ โดยไม่ต้องเดา สลิป / ค่าส่ง / รอบจอง / แอดมิน
- **Constraint:**
  - นักศึกษาไม่มีล็อกอิน — กรอกข้อมูล + ติดตามด้วยรหัสออเดอร์/ลิงก์
  - จองได้เรื่อยๆ ไม่ล็อกสต็อก realtime
  - สลิปต้องผ่าน checksum จาก QR เบื้องต้นก่อนจบการจอง แล้วค่อยเข้าคิวให้เจ้าหน้าที่ตรวจ/ยืนยัน
  - ค่าส่งเป็นเรทคงที่ (1–2 เรท) รวมในยอด PromptPay ตอน checkout
  - หน้าร้านโชว์เฉพาะสินค้าในรอบที่เปิดอยู่; รอบเปิดจองผูกช่วงเวลา **และ** สินค้า
  - แอดมินจัดการสินค้าได้เต็มรูปแบบ (เพิ่ม/ปิดขาย/แก้ตัวเลือก/ราคา)
- **Out of scope (v1):**
  - Pickup assist = Phase 2 (อยู่ในเอกสารเดียวกัน แต่ไม่บล็อกรับมอบ v1)
  - Ads banner = หลัง v1 — ดู `docs/intent/ads-banner.md`
  - ไม่มี verify สลิปอัตโนมัติแทนคนทั้งกระบวนการ
  - ไม่บังคับล็อกสต็อก realtime
  - ไม่บังคับล็อกอินนักศึกษา

## Decisions captured during grill

| หัวข้อ | คำตอบ |
| --- | --- |
| ขอบเขตเอกสาร | ฝั่งนักศึกษา + เจ้าหน้าที่ในชุดเดียว |
| หลังแนบสลิป | checksum QR เบื้องต้น → คิวเจ้าหน้าที่ |
| Checksum ไม่ผ่าน | บล็อกไม่ให้จบการจอง |
| สต็อก | จองได้เรื่อยๆ ไม่ล็อก |
| Auth นักศึกษา | ไม่มีล็อกอิน |
| ค่าส่ง | เรทคงที่รวมในยอดชำระ |
| แค็ตตาล็อก | หลังบ้านจัดการเต็มรูปแบบ |
| Pickup assist | Phase 2 / optional ใน SRS เดียวกัน |
| รอบเปิดจอง | มี; ผูกสินค้าด้วย ไม่ใช่แค่หน้าต่างเวลา |
