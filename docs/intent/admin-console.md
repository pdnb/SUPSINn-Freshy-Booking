## Confirmed statement

- **Outcome:** แอดมิน Livewire ที่เจ้าหน้าที่ใช้ได้จริง — ครบจอตาม `admin-mockup` รวมรับของแบบค้นรหัส และมีหน้าสต็อก (ของที่มี vs ออเดอร์ที่ยืนยัน)
- **User:** เจ้าหน้าที่ 1–ไม่กี่คน วันเปิดจอง (คิวสลิป + จัดส่ง) และวันรับของ (ค้นแล้วติ๊กสถานะ)
- **Why now:** แอดมินเก่าถูกลบเหลือล็อกอิน mockup พร้อมแล้ว ต้องมีระบบหลังบ้านจริง
- **Success:** เดินภาพรวม → คิวสลิป (ดูสลิป/ยืนยันหรือปฏิเสธ → ถัดไป) → จัดส่ง ได้ลื่น; จัดการสินค้า/รอบจอง/ตั้งค่าได้; เปิดสรุปผลิตได้; ค้นรับของได้; ปรับยอดของที่มีแล้วเห็นเทียบออเดอร์
- **Constraint:** อยู่ Livewire + services ที่มี ไม่ใช้ Filament; เลย์เอาต์จอตาม `admin-mockup` แต่พอร์ต CSS จาก `ecommerce-admin`; สต็อกไม่บล็อก checkout; หน้าสต็อกยึดแพทเทิร์นตาราง+dialog ของ ecommerce-admin
- **Out of scope:** ลูกค้า CRM, โค้ดส่วนลด, กราฟรายได้, บล็อกจองเมื่อหมดสต็อก, pickup assist เต็มรูป (สแกน/คิวเรียก), auto-verify สลิป, ย้ายไป admin kit อื่น

## Decisions captured during grill

| หัวข้อ | คำตอบ |
| --- | --- |
| โมดูลร้านทั่วไป | สต็อกเป็นงานจริง — ลูกค้า / ส่วนลด / กราฟเลื่อน |
| สต็อกกับ checkout | ยังจองได้เมื่อยอดเป็น 0 — สต็อกเป็นเครื่องมือเจ้าหน้าที่ |
| ตัวเลขสต็อก | ของที่มีจริง/จากโรงงาน ตั้งและปรับเอง แล้วเทียบออเดอร์ที่ยืนยัน |
| ขอบเขตจอ | ครบทุกจอใน mockup รวมรับของ และเพิ่มสต็อก |
| รับของ | ค้นรหัสนักศึกษา/ออเดอร์ แล้วอัปเดตสถานะ — ไม่ใช่แอปหน้างาน |
| CSS | พอร์ต `admin-common.css` ไม่พอร์ต `tokens.css` / `shell.css` ของ mockup |

## Non-goals (ชัดเจน)

- Filament / admin kit
- ลูกค้า CRM, โค้ดส่วนลด, กราฟรายได้
- บล็อก checkout เมื่อหมดสต็อก
- pickup assist เต็มรูป
- auto-verify สลิปแทนคน
- ใส่ SKU หรือสต็อกขายในแคตตาล็อก
