# Intent: แพ็คของ (printable packing checklist)

| รายการ | ค่า |
| --- | --- |
| สถานะ | Confirmed |

พิมพ์ใบ checklist ต่อออเดอร์ แล้วมาร์คว่าแพ็คแล้วด้วยพิมพ์รหัสหรือสแกน — ไม่ใช่ใบปะหน้า ไม่เชื่อมขนส่ง ไม่เปลี่ยนสถานะตอนพิมพ์ ร้าน/หอที่แพ็คแล้ว = พร้อมรับของ

## Confirmed statement

- **Outcome:** หน้าแอดมิน **แพ็คของ** พิมพ์กองใบ checklist หนึ่งออเดอร์ต่อหน้า แล้วเจ้าหน้าที่พิมพ์หรือสแกนรหัสออเดอร์เพื่อมาร์คว่าแพ็คแล้ว ให้ใบนั้นหายจากกองพิมพ์รอบถัดไป สำหรับร้าน/หอ สแกนนั้นตั้ง `packed_at` และสถานะ **พร้อมรับของ** ในก้าวเดียว นักศึกษาเห็นพร้อมรับทันที
- **User:** เจ้าหน้าที่แพ็คของที่โต๊ะ (ทุกช่องทาง มีจอ + พิมพ์รหัสหรือสแกนเนอร์) และนักศึกษาที่รอรับที่ร้าน/หอ
- **Why now:** พิมพ์แล้วออเดอร์ยังอยู่ในกองเดิม จึงพิมพ์ซ้ำได้ทั้งที่แพ็คไปแล้ว — และร้าน/หอไม่ควรต้องไปกดพร้อมรับอีกทีหลังแพ็ค
- **Success:** กรองรอบจอง / ช่องทาง / คณะ แล้วพิมพ์ PDF ทั้งกอง; เรียง **ช่องทาง (ไปรษณีย์ → ร้าน → หอ) → คณะ → รหัสออเดอร์**; แต่ละใบมีผู้จองครบ + รายการ/ไซส์/จำนวน + ช่องติ๊กว่าง + บาร์โค้ด Code128 และ QR ของรหัสออเดอร์; พิมพ์อย่างเดียวยังไม่ถือว่าแพ็ค; พิมพ์/สแกนรหัสบนหน้าแพ็คของแล้วออเดอร์หลุดจากกอง; ย้อนกลับได้ทั้งช่องรหัสและรายการแพ็คแล้ววันนี้; ร้าน/หอที่สแกนแล้วเป็นพร้อมรับของ (นักศึกษาเห็น) และยกเลิกแพ็คแล้วย้อนเป็นยืนยันการชำระแล้ว; ไม่มีปุ่มพร้อมรับบนหน้าจัดส่ง; จุดรับของยังกดรับของแล้ว; ไปรษณีย์แพ็คแล้วแค่หลุดกองพิมพ์ ยังกดจัดส่งแล้ว + เลขพัสดุบนหน้าเดิม
- **Constraint:**
  - Livewire SFC หน้าแอดมินตามเดิม ไม่ใช่ Filament
  - PDF แนวเดียวกับสรุปยอด (DomPDF + Sarabun + Code128 + QR)
  - กองพิมพ์ = confirmed + พร้อมรับ + ไปรษณีย์ที่ยังไม่มีเลขพัสดุ **และ** `packed_at` ว่าง
  - มาร์คแพ็คแล้วเก็บที่ `orders.packed_at` ไม่ใช่ `OrderStatus` ใหม่ — ร้าน/หอใช้ `ReadyForPickup` ที่มีอยู่แล้ว ไม่สร้างสถานะแพ็คแล้ว
  - ชื่อที่คนเห็นคือ **แพ็คของ** (เมนู ชื่อหน้า หัวข้อ/ไฟล์ PDF) — ไม่ใช้ ใบแพ็ค / แพ็คสินค้า
  - ไปรษณีย์ไม่แตะ `markShipped` / เลขพัสดุ จากหน้าแพ็คของ
- **Out of scope:**
  - ใบปะหน้าขนส่ง
  - เชื่อมไปรษณีย์/Kerry
  - ยอดหยิบรวมแบบสรุปยอด
  - ติ๊กทีละชิ้นบนจอแล้ว sync
  - พิมพ์แล้วถือว่าแพ็คอัตโนมัติ
  - ราคา/ยอดเงินบนใบ
  - สถานะ «แพ็คแล้ว» ฝั่งนักศึกษา (ร้าน/หอเห็น **พร้อมรับของ**)
  - แพ็คแล้ว = จัดส่งแล้ว
  - แพ็คแล้ว = รับของแล้ว
  - ตัดช่องทางไปรษณีย์
  - คอลัมน์แพ็คแล้วบนหน้าจัดส่ง/รับของ
  - LINE / SMS
  - เช็คลิสต์ฝั่งนักศึกษา
  - CSV / Excel
  - Filament

## Decisions captured during grill

| หัวข้อ | คำตอบ |
| --- | --- |
| สิ่งที่ต้องการ | ใบ checklist พิมพ์ออกมาได้ ถือไปโต๊ะแพ็ค |
| หน่วยของใบ | หนึ่งออเดอร์หนึ่งใบ — ไม่ใช่ยอดรวมหยิบ |
| ช่องทาง | ทุกช่องทาง (ไปรษณีย์ / ร้าน / หอ) |
| วิธีพิมพ์ | กองทีเดียว: กรองแล้วพิมพ์ PDF ทั้งกอง หนึ่งออเดอร์ต่อหน้า |
| ฟิลด์บนใบ | ผู้จองครบ (ชื่อ, รหัสนักศึกษา, โทร, คณะ, สาขา, ช่องทาง, ที่อยู่หรือจุดรับ) + รายการ/ไซส์/จำนวน + ช่องติ๊ก — ไม่มีราคา |
| สถานะที่พิมพ์ | confirmed + พร้อมรับ + ไปรษณีย์ที่ยังไม่มีเลขพัสดุ และยังไม่แพ็ค |
| เรียงกอง | ช่องทาง → คณะ → รหัสออเดอร์; ลำดับช่องทาง = ไปรษณีย์ → ร้าน → หอ |
| ที่อยู่ปุ่ม | หน้าแอดมินใหม่ **แพ็คของ** |
| พิมพ์แล้วสถานะ | ไม่เปลี่ยน |
| ช่องติ๊ก | ทีละบรรทัดสินค้า (ไม่ใช่ทีละตัวเลือก) |
| ระบบรู้ว่าแพ็คเสร็จ | พิมพ์หรือสแกนรหัสออเดอร์ — ไม่พิมพ์ซ้ำ |
| วิธีใส่รหัส | ทั้งพิมพ์และสแกน (บาร์โค้ด Code128 และ QR บนใบ) |
| ย้อนกลับ | ได้ทั้งช่องรหัส (ยกเลิกแพ็คแล้ว) และรายการแพ็คแล้ววันนี้ |
| แพ็คแล้ว = พร้อมรับ | ร้าน/หอเท่านั้น — ไปรษณีย์ยังกดจัดส่งแล้ว + เลขพัสดุ |
| ปุ่มพร้อมรับ | ตัดออก — ทางเดียวที่จะพร้อมรับคือสแกน/พิมพ์รหัสบนหน้าแพ็คของ |
| ย้อนแพ็คแล้ว (ร้าน/หอ) | กลับเป็นยืนยันการชำระแล้ว นักศึกษาไม่เห็นพร้อมรับอีก |
| รับของแล้ว | เก็บปุ่มไว้ที่จุดรับของ |

## Non-goals (ชัดเจน)

- ใบปะหน้า / พิมพ์ที่อยู่แยก / เชื่อมขนส่ง
- ยอดหยิบรวมสินค้า × ตัวเลือก (มีอยู่แล้วที่สรุปยอด)
- ติ๊กทีละชิ้นบนจอแล้วบันทึก
- พิมพ์แล้วถือว่าแพ็คอัตโนมัติ
- ราคา ยอดสุทธิ สลิป เลขพัสดุ บนใบ
- สถานะแพ็คแล้วฝั่งนักศึกษา / คอลัมน์บนจัดส่ง-รับของ
- แพ็คแล้ว = จัดส่งแล้ว หรือรับของแล้ว
- ตัดช่องทางไปรษณีย์
- LINE/SMS, verifier, roles, API โรงงาน, Filament
- เช็คลิสต์นักศึกษา
