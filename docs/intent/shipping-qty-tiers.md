## Confirmed statement

- **Outcome:** แอดมินตั้งช่วงจำนวนได้ต่อเรทค่าส่ง แล้ว checkout คิดยอดตามจำนวนในตะกร้า
- **User:** แอดมินตั้งสูตร / นักศึกษาเห็นยอดในสรุปอย่างเดียว (ไม่เลือกเรท)
- **Why now:** เรทคงที่ทำให้ส่ง 1 ชิ้นกับหลายชิ้นราคาเท่ากัน — ต้องการคิดตามจำนวนจริง
- **Success:** ตั้งช่วงเช่น 1 = 50, 2–3 = 80, 4+ = 120 แล้วยอดไปรษณีย์ตรงตามผลรวม qty ทุกบรรทัด
- **Constraint:**
  - นับชิ้น = รวม qty ทุกบรรทัดในตะกร้า (คอมโบ 1 + เสื้อ 2 = 3)
  - จำนวนที่เกินช่วงที่ใช้ได้ ใช้ยอดของช่วงสูงสุดที่มี (`min_qty` สูงสุดที่ยัง `<=` จำนวน)
  - รับที่ร้าน/หอ: ค่าส่ง 0 ตามเดิม
  - ลูกค้าไม่เลือกเรท — ใช้เรท active แรกตาม `sort_order`
- **Out of scope:**
  - คิดตามจังหวัด / รหัสไปรษณีย์
  - ส่งฟรีตามยอดสินค้า
  - ให้ลูกค้าเลือกเรท
  - น้ำหนักต่อสินค้า
  - เลขพัสดุ

## Decisions captured during grill

| หัวข้อ | คำตอบ |
| --- | --- |
| ตัวขับยอด | จำนวนชิ้น/ชุดในตะกร้า |
| สูตร | ช่วงจำนวน (tier) ไม่ใช่คิดต่อชิ้นเท่ากัน |
| หน่วยนับ | รวม qty ทุกบรรทัด |
| เกินช่วง | ใช้ยอดของช่วงสูงสุดที่มี |
| เก็บข้อมูล | JSON `tiers` บนเรทเดิม คง `amount` เป็นยอดช่วงแรก |
| จับคู่ | เรียงตาม `min_qty` แล้วเลือกช่วงสุดท้ายที่ `min_qty <= cartQty` — `max_qty` เป็นตัวช่วยในฟอร์ม |

## Non-goals (ชัดเจน)

- โซนจัดส่ง / รหัสไปรษณีย์
- ยอดขั้นต่ำส่งฟรี
- ให้แขกเลือกเรทบนหน้าร้าน
- น้ำหนักหรือหน่วยนับที่แอดมินตั้งต่อสินค้า
