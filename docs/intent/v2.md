## Confirmed statement

- **Outcome:** แผนหลัง v1 แบบส่งทีละสไลซ์: สรุปยอดสั่งโรงงานได้ → เคลียร์ fulfillment ตามช่องทาง → คิวตรวจสลิปลื่น → รับของหน้างานเร็ว → แบนเนอร์หน้าร้าน
- **User:** เจ้าหน้าที่แอดมิน/หน้างานเป็นหลัก; โรงงานรับยอดผ่านไฟล์ที่แอดมินส่งเอง; นักศึกษาได้ประโยชน์ทางอ้อม (สถานะ/รับของชัดขึ้น) + เห็นแบนเนอร์
- **Why now:** v1 จอง–จ่าย–คิวพื้นฐานครบแล้ว; ขั้นถัดไปคือ ops จริง (ผลิต → จ่ายของ → รับของ) และโมดูลที่เลื่อนไว้ (ads)
- **Success / ลำดับบังคับ:**
  1. **Production summary** — กรอง **รอบจอง** และ **คณะ** (`orders.faculty`, ค่าเริ่มต้น = ทุกคณะ); นับเฉพาะออเดอร์ที่ยืนยันสลิปแล้ว; ตารางสินค้า × ตัวเลือก (รวมชิ้นใน bundle); ดูบนแอดมิน + ดาวน์โหลด **CSV / PDF / Excel**; ไม่แยกจุดรับ / ไม่ API โรงงาน
  2. **Fulfillment** — คิวตามช่องทาง (ร้าน / หอ / ไปรษณีย์) + เปลี่ยนสถานะจนจบ (พร้อมรับ → รับครบ+ใบเสร็จ หรือ shipped → เสร็จ) โดยไม่มีเลขพัสดุ/พิมพ์/ขนส่ง
  3. **Queue redesign** — ตาม `docs/intent/admin-redesign.md` (ลูป approve/reject ต่อเนื่อง)
  4. **Pickup** — เจ้าหน้าที่หน้างานค้นรหัสออเดอร์/รหัสนักศึกษา เห็นรายการ+ไซส์+จุดรับ รับครบ+ใบเสร็จเร็ว (ไม่มี claim lock / สแกนฮาร์ดแวร์ / จอคิว)
  5. **Ads** — ตาม `docs/intent/ads-banner.md`
- **Constraint:**
  - อยู่บน Livewire + `app/Services` / `app/Contracts` เดิม — ไม่ย้าย Filament
  - ไม่เปลี่ยนกฎธุรกิจออเดอร์/สต็อกเป็นหลัก — v2 เป็น UI / query / aggregation ใหม่
  - ลำดับสไลซ์บังคับตาม Success ข้างบน
  - โรงงานรับไฟล์จากแอดมินเอง ไม่มีการเชื่อมระบบ
- **Out of scope (v2):**
  - เช็คลิสต์นักศึกษาจาก mockup `pickup-assist.html`
  - เลขพัสดุ / ใบปะหน้า / packing list / เชื่อมขนส่ง
  - API โรงงาน / PO อัตโนมัติ
  - แจ้งเตือน LINE/SMS
  - slip verifier จริง / QR PromptPay dynamic
  - roles หลายระดับ, auto-verify แทนคน, ย้าย Filament

## Decisions captured during grill

| หัวข้อ | คำตอบ |
| --- | --- |
| ขอบเขต “v2” | ไม่ใช่แค่ pickup — queue redesign + pickup + fulfillment + ads + อื่นๆ |
| ความหมาย fulfillment | งานหลัง approve: คิวแยกช่องทาง + ทำสถานะพร้อมรับ/ส่งแล้ว/รับครบ+ใบเสร็จ |
| Fulfillment “พอแล้ว” | เปลี่ยนสถานะจนจบได้ลื่น — ไม่มีเลขพัสดุ/ใบปะหน้า/ขนส่ง/packing list |
| Pickup เป็นของใคร | เจ้าหน้าที่หน้างาน (SRS FR-PCK-01) ไม่ใช่เช็คลิสต์นักศึกษา |
| Pickup “พอแล้ว” | ค้นรหัสออเดอร์/รหัสนักศึกษา → รายการ+ไซส์+จุดรับ → รับครบ+ใบเสร็จ |
| ถุง “อื่นๆ” | ช่องว่างเผื่อไว้ (แจ้งเตือน, verifier จริง, QR dynamic) — ไม่อยู่เกณฑ์รับมอบ v2 |
| โมดูลเพิ่มระหว่าง grill | สรุปยอดเพื่อสั่งโรงงานผลิต |
| ลำดับของ production summary | **ก่อน** fulfillment |
| นับสถานะไหน | เฉพาะที่ยืนยันสลิปแล้ว — ตัด `pending_review` / ปฏิเสธ / ยกเลิก |
| มิติสรุป | สินค้า × ตัวเลือก (รวมชิ้นใน bundle) ต่อรอบจอง; ไม่แยกจุดรับ |
| ฟิลเตอร์เพิ่มหลังยืนยัน | กรองตามคณะได้ (ค่าเริ่มต้น = ทุกคณะ) |
| รูปแบบส่งออกหลังยืนยัน | CSV + PDF + Excel (.xlsx) จากข้อมูลชุดเดียวกับตารางบนจอ |

## Non-goals (ชัดเจน)

- เชื่อมระบบโรงงาน / สร้าง PO อัตโนมัติ
- ระบบขนส่ง (tracking, ใบปะหน้า, packing list)
- Student-facing pickup checklist
- Filament / admin kit migration
- เปลี่ยนกฎ transition ของ `OrderService` หรือกฎสต็อก
